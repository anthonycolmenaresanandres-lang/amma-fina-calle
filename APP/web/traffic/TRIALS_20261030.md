## Metrics and attribution

| Brand | Menu pageview destination | Game-page view | Start | Completion |
| --- | --- | --- | --- | --- |
| project-seed | /demo/project-seed | /play/project-seed | New-run Start action (loading may still fail) | All three rounds succeed |
| el-mariachi | /el-mariachi | /el-mariachi/play | User starts/replays a round | Round reaches its result, by timer or clearing the courtyard |

The stable /project-seed/menu redirect is excluded; only its destination counts.
Loading a game landing page is not a start. Seed retry/next-round actions stay in
the same run; abandoning it is not completion. El Mariachi pause/resume are not
starts; a result does not assert a win. Replays are additional starts. Completion
definitions differ intentionally by game and must accompany the brand report.
There is no player/session stitching or conversion-rate guarantee: starts and
completions in a selected interval can belong to runs spanning its boundary.

Only verified finacalleos.com/www.finacalleos.com exact public paths are accepted.
The server derives site_id from hostname+path, never caller tenant/brand fields.
Query/hash data, location selectors, scores, visitor IDs and arbitrary custom
properties are not stored. El Mariachi location choices are not a location-level
measurement or business account identifier. Both route classifications remain
concept, without claiming acceptance or enrollment.

## One ingestion path, existing schema

TRAFFIC_TRIAL_COLLECTION_ENABLED defaults off. When explicitly approved and true
in production, the existing anonymous collector runs in trials-only mode if the
broader TRAFFIC_INGESTION_SOURCE remains disabled/drain. It uses the existing
/api/traffic/pageview endpoint. No second script is mounted if broad first-party
collection is later enabled: the one script handles all pageviews once. All
trial events still require the trial flag when broader collection is on;
the client/server exclude these two brands when it is off. Games
send only game_start/game_complete to the same endpoint, guarded once per run in
memory. Preview and disabled requests never access storage.

Existing established-drain receiver/parser/registry are byte-identical to main.
They continue handling Bodega/Fina/Colattao and exclude these two trial brands.
Native Vercel Analytics remains mounted and is a separate source; NEVER add its
counts to the dedicated first-party report. Do not add trial brands to the drain
while these first-party events are active, or dual sources could count a visit twice.

Current eight-column traffic_events already supports site_id, event_type and a
unique event_key. No migration or runtime DDL is introduced. Random event IDs
deduplicate a repeated request in storage, with different IDs for start/complete.
They are not persistent visitor IDs: no new cookie, localStorage value, account,
IP, fingerprint, score or raw visitor record. Existing Seed personal-best storage
is unchanged and is never included. Requests omit credentials, fail silently with
a three-second bound and no blind retries. DNT/GPC/internal-QA markers suppress
the client. Existing per-instance admission/body/origin restrictions remain;
public client events are best effort and do not prove human activity.

## Reports and coverage

For each whole selected interval, aggregate menu pageviews, game-page views,
game starts and completions separately for each brand. Existing pageview totals,
whole-period tracked-identifier semantics and Bodega/Colattao queries remain.
Lifecycle events never inflate pageviews or identifiers. Optional path filters
and inclusive-start/exclusive-end bounds apply to all metrics. SQL failures make
the report unavailable; they are never turned into zeros. Existing HTML/text
reports include the four trial counts with explicit unverified coverage.

Collection probes still prove configuration only. No pageviews/checks -> waiting;
recorded pageviews without verified complete ingestion -> partial; failed/stale
checks -> stale. No probe, healthy page, deploy or test authorizes measured-zero
traffic. Pageviews/events are neither people nor physical QR scans. Overlapping
daily/weekly numbers or cross-brand identifiers must not be added. There is no
historical backfill. A report period must be agreed only after owner acceptance,
dates and actual collection verification.

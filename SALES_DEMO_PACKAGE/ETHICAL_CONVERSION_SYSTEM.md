# Ethical Conversion System

## Objective

Move a qualified prospect to one voluntary, dated next action. The system improves clarity, relevance, proof, and follow-through. It does not attempt to bypass judgment or informed choice.

## Evidence posture

Before choosing a message, separate the evidence:

- **Known:** directly stated by the owner or observed in a documented interaction.
- **Inferred:** a reasonable hypothesis that must be tested, not presented as fact.
- **Missing:** information that requires one discovery question.

Do not infer personality, fear, income, protected traits, or vulnerability. Keep real contact and interaction data in the private owner-held tracker, never the public repository.

## One decision path

1. **Recognition:** repeat one stated priority in the owner's language.
2. **Outcome:** describe one practical improvement without guaranteeing results.
3. **Proof:** show the narrowest verified proof that supports the outcome.
4. **Friction reduction:** explain what the owner does not have to install, manage, or risk.
5. **Pilot:** offer a reversible, written, clearly bounded next step.
6. **Action:** ask for one specific response or dated action.

If the priority is unknown, ask: **“What matters more right now: making menu updates easier, improving the in-store experience, or keeping the setup simple?”**

## Priority-to-proof map

| Stated priority | Recognition | Verified proof | Appropriate action |
|---|---|---|---|
| Time / simplicity | “You should not have to wait on a developer for a price change.” | Owner sign-in and self-edit workflow | Request a written setup outline |
| Brand / differentiation | “You want the scan to feel like your business, not a generic page.” | Colattao menu plus the playable game engine demo | Approve a private visual mock |
| Trust / skepticism | “You want to see what is real before discussing a package.” | Live Colattao menu and feature-status table | Review a written pilot scope |
| Price / risk | “You need the cost and boundaries before committing.” | $199 starting price and written exclusions | Request the $199/month plan in writing |
| Customer experience | “You want a more useful in-store scan.” | Live menu plus clearly labeled game demo | Test a bounded pilot |

## Experiment discipline

Assign one `hook_id`, `proof_id`, `cta_id`, and `offer_id` to every exposure. Change one material variable at a time. Use `CONVERSION_EXPERIMENT_LOG_TEMPLATE.csv` for the schema and the private tracker for real data.

Primary metrics:

- qualified exposures;
- demos shown;
- dated next actions accepted;
- proposals sent;
- closes;
- time from exposure to next action.

Guardrails:

- declines and unsubscribe requests;
- complaints;
- misunderstanding about price, recurring terms, feature status, or privacy;
- follow-up without consent.

Stop an experiment immediately if it creates material misunderstanding, uses an unsupported claim, or increases complaints. Do not declare a pattern without the sample size, conversion counts, loss reasons, and experiment dates.

## Prohibited tactics

No fabricated scarcity, fake testimonials or activity, disguised advertising, hidden pricing or recurring terms, preselected consent, obstruction, shame, exaggerated fear, bait-and-switch offers, confusing cancellation, invented customer quotes, or targeting based on protected traits or vulnerability.

3. Resolve every blocking issue.
4. Confirm one proof and one call to action.
